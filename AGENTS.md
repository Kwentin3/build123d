# CAD-пилот

- Для CAD-задачи используй нативный `cad-entry` из `.agents/skills/`;
  остальные CAD Skills загружай по задаче, без чтения всех справочников.
  Если host не обнаруживает Skills, прочитай `.agents/skills/cad-entry/SKILL.md`
  напрямую и явно отметь ограничение автоматического обнаружения.
- Перед использованием сохранённого отчёта сравни его source/dependency/artifact
  SHA-256 с файлами по примеру README.md. Старый PASS после изменения исходника
  не является текущей приёмкой. Процесс описан в WORKFLOW.md.

- Используй штатные API build123d/Open Cascade; ядро библиотек не изменяй.
- Геометрия хранится в редактируемом Python-коде `models/<name>/`;
  именованные параметры — в начале файла, размеры — в миллиметрах.
- Модели независимы; результаты — в `output/<name>/`. Сохраняй обход
  кириллических путей штатного STL-экспорта на Windows.
- После изменений запускай модель, её проверки и `python -m pytest -q`
  через `.venv/Scripts/python.exe`. Проверяй STEP после повторного импорта.
- Для пластины читай `output/plate/report.json`: сравни измеренное с заданием,
  разбирай `FAIL` и причины `NOT_CHECKED`, исправляй наблюдаемое расхождение
  и повторяй проверку. Код выхода 0 сам по себе не доказывает корректность.
- Снимки: существующий OCP CAD Viewer и `--screenshots`. Открой полученные PNG
  перед визуальными выводами. Снимок не подтверждает численные размеры.
- Не утверждай проверку характеристик без соответствующих evidence;
  различай инженерное несоответствие, технический сбой и отсутствие проверки.
- Делай минимальные изменения. Зависимости добавляй только с конкретным
  обоснованием; менеджер проектов, сервер и агентный фреймворк здесь не нужны.
