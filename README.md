# Локальный пилот build123d

Пластина 100 × 60 × 8 мм с центральным сквозным отверстием Ø12 мм.
Начало координат — центр детали; X — ширина, Y — высота, Z — толщина.
Параметры `WIDTH`, `HEIGHT`, `THICKNESS`, `HOLE_DIAMETER` находятся в начале
`models/plate/model.py`.
Модель использует штатную разность `Box - Cylinder`, без изменения build123d.

Независимый эксперимент с эвольвентной шестернёй: [models/gear/README.md](models/gear/README.md).
Его исходники, валидатор и тесты находятся только в `models/gear/`, результаты —
в `output/gear/`. Прежняя пластина и её 12 тестов сохранены.

Текущий релиз мангала: [2.1 — пять деталей, без чек](models/mangal_v21/README.md).
[Выпуск 2.0](models/mangal_v2/README.md), исходная конструкция и исследование клина сохранены для сравнения.

## Структура

```text
models/
  plate/
    model.py              # самостоятельная модель пластины
    validation.py         # измерения и проверки только этой пластины
tests/
  test_model.py           # четыре проверки пластины
output/
  plate/
    plate_100.step
    plate_100.stl
    plate_120.step
    plate_120.stl
    preview.png           # проверенный снимок OCP CAD Viewer
    report.json           # результат последнего запуска, не история
    top.png / side.png / iso.png  # при --screenshots
.vscode/                  # интерпретатор, тесты и F5
requirements.txt          # общее окружение с фиксированными версиями
AGENTS.md                 # краткие инструкции Codex
README.md
.gitignore
```

`.venv/`, `output/` и служебные кэши исключены из Git. У каждой модели своя
папка исходников и своя папка экспорта; общего менеджера моделей нет.

## Запуск в PowerShell

Активация окружения и изменение ExecutionPolicy не требуются:

```powershell
.\.venv\Scripts\python.exe models/plate/model.py
.\.venv\Scripts\python.exe models/plate/model.py --width 120
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Экспорт: `output/plate/plate_100.step`, `output/plate/plate_100.stl`
и варианты `output/plate/plate_120.*`.
Повторный запуск без аргументов воспроизводит исходную деталь, если параметры
в начале файла не изменены. `--width` меняет только текущий запуск.
Вывод содержит путь отчёта, итоговый статус, код выхода, габариты и объём.
Подробные измерения, проверки и пути STEP/STL находятся в `report.json`.
Папку экспорта можно задать через существующий `--output-dir` (относительный
путь этого аргумента считается от текущего каталога). Путь по умолчанию
вычисляется через `Path(__file__).resolve().parents[2] / "output" / "plate"`,
поэтому запуск скрипта из другого рабочего каталога также корректен.

## Просмотр в VS Code

1. Открыть эту папку в VS Code: `code .`.
   Если расширения только что установлены в уже открытый VS Code, сначала
   выполнить `Ctrl+Shift+P` → `Developer: Reload Window`.
2. При запросе доверия проверить и подтвердить доверие этой папке.
3. `Python: Select Interpreter` → `.venv/Scripts/python.exe`, если VS Code
   ранее запомнил другой интерпретатор. Значение по умолчанию уже задано
   в `.vscode/settings.json`.
4. Открыть `models/plate/model.py`. Расширение должно автоматически открыть просмотрщик;
   иначе выполнить `OCP CAD Viewer: Open viewer` через `Ctrl+Shift+P`.
5. Выполнить конфигурацию `CAD: model + viewer` через F5 либо в терминале:

```powershell
.\.venv\Scripts\python.exe models/plate/model.py --show
.\.venv\Scripts\python.exe models/plate/model.py --screenshots
```

Для второго варианта: `models/plate/model.py --width 120 --show`.
F5 использует явный путь к скрипту пластины и `.venv/Scripts/python.exe`;
рабочий каталог — корень проекта.
Обычный запуск без `--show` не зависит от наличия окна просмотрщика.
Просмотр использует штатный локальный механизм расширения OCP CAD Viewer;
отдельный сервер проекта не нужен.
`--screenshots` также показывает модель и сохраняет свежие `top.png`,
`side.png` (камера RIGHT, вдоль X) и `iso.png` через штатные `Camera` и
`save_screenshot`. Перед снимком старый файл удаляется; новый PNG проверяется
через уже установленный Pillow. При отсутствии viewer геометрия и экспорт
всё равно проверяются; запрошенный просмотр завершится технической ошибкой
с кодом 2, а недоступные визуальные проверки останутся `NOT_CHECKED`.
Без `--show`/`--screenshots` viewer не требуется.

Если команда `OCP CAD Viewer: Open viewer` сообщает
`command 'ocpCadViewer.ocpCadViewer' not found`, расширение не зарегистрировало
команду в текущем окне. В пилоте это наблюдалось после установки OCP CAD Viewer
до завершения установки его обязательной зависимости `ms-python.python`;
в журнале старого окна активация OCP отсутствовала. Сначала выполнить
`Developer: Reload Window`, затем повторить `Open viewer`. Если ошибка
сохранилась, открыть `Developer: Show Logs...` → `Extension Host` и проверить
ошибку активации `bernhard-42.ocp-cad-viewer`. Повторная установка Python-пакетов
не исправляет отсутствие зарегистрированной команды VS Code.

   отправку модели выполнять через штатный `ocp_vscode.show`.
   Конфигурацию пластины оставить доступной.

## Проверки

Прежние четыре теста сохранены и дополнены: всего **12 тестовых случаев**.
Они строят оба размера и запускают CLI в отдельных процессах.
Проверяются одно валидное тело, габариты, аналитический объём, единственная
цилиндрическая поверхность радиуса 6 мм на всю толщину и две круглые кромки
с центрами на оси Z на обеих поверхностях. STEP повторно импортируется и
проходит те же проверки; STL повторно импортируется для проверки габаритов.
Проверка STL не является полной проверкой замкнутости треугольной сетки.
Тестовый экспорт выполняется во временные каталоги pytest.
Дополнительные отрицательные случаи: неправильный ожидаемый размер,
смещённое/глухое/отсутствующее отверстие, неправильная толщина, ошибочный
параметр построения и нечисловые `nan`/`inf` после прежнего успешного отчёта.

При каждом запуске `validation.py` измеряет фактическую геометрию через
build123d/Open Cascade: `BRepCheck_Analyzer`, количество тел, bounding box,
плоские поверхности толщины, цилиндрическую стенку и круговые кромки отверстия.
Дополнительно проверяется отсутствие материала на оси отверстия на трёх
уровнях по Z через штатный классификатор твёрдого тела. Это независимые
наблюдения результата, а не повторение команды вычитания цилиндра.
Объём сравнивается с аналитическим объёмом прямоугольника минус круг,
умноженным на толщину. После импорта STEP повторяются все проверки.

Допуски: размеры **1e-6 мм**, объём **1e-3 мм³** либо относительный **1e-8**;
для габаритов триангулированного STL — **1e-5 мм**. Эти численные допуски
не являются допусками реального производства.

## Машинная обратная связь

Каждый запуск перезаписывает `output/plate/report.json` (UTF-8).
При `--output-dir` отчёт хранится в указанной папке вместе с экспортом.
Это локальный отчёт пластины, без базы данных и универсальной схемы валидации.

- `parameters`, `expected_parameters`, `units` — входные размеры и проверяемое
  задание; `actual` и `step_actual` — фактические измерения.
- `checks` — **PASS**, **FAIL** или **NOT_CHECKED** для каждой проверки,
  с фактом, ожиданием, допуском либо причиной отсутствия проверки.
- `errors` разделяет `engineering` (измеренное не соответствует заданию)
  и `technical` (построение, измерение, ввод/вывод или viewer не отработали).
- `artifacts` содержит только подтверждённые в текущем запуске файлы.
  Файлы от прежнего запуска могут физически оставаться в каталоге,
  но не становятся артефактами нового отчёта автоматически.
- `engineering_status`, `execution_status`, `status`, `exit_code` разделяют
  инженерную проверку и выполнение. Для успеха обязательны все проверки
  построения, геометрии, экспорта и повторного импорта.

Коды процесса: **0** — обязательные проверки прошли; **1** — инженерное
несоответствие; **2** — техническая ошибка или неполная обязательная проверка.
Не запрошенные снимки не мешают успеху геометрии, но остаются `NOT_CHECKED`.
`visual_review` всегда `NOT_CHECKED`: программа проверяет создание PNG,
а не его инженерный смысл. Агент должен отдельно открыть изображения,
описать увиденное и сопоставить с заданием. Точные размеры доказываются
численными проверками, а не картинкой.

При недоступном каталоге отчёта запись JSON физически невозможна:
процесс возвращает 2 и пишет техническую причину в stderr. В этом случае
нельзя принимать старый `report.json` за результат нового запуска.

Намеренно неверное ожидание можно задать через обычный Python API, без
нового CLI или правки исходной геометрии:

```python
from models.plate.model import run_plate

raise SystemExit(run_plate(
    output_dir="output/plate/negative",
    expected=dict(width=120, height=60, thickness=8, hole_diameter=12),
))  # строится исходная пластина 100 мм: FAIL, код 1
```

Контрольный эксперимент использует `output/plate/` (100 мм),
`output/plate/variant_120/` (120 мм) и `output/plate/negative/` (ошибочное
ожидание 120 мм при фактических 100 мм). Последний запуск восстанавливает
исходные 100 мм в основной папке. Имена параметров в исходнике не меняются.

Ограничения: нет проверки прочности, технологичности, производственных
допусков или замкнутости STL-сетки; геометрический валидатор относится только
к этой пластине. Снимкам нужен работающий viewer в VS Code. Новые модели
получают собственные проверки по заданию; валидатор пластины не универсален.

## Использованные подходы

Изучены официальные [build123d import/export](https://build123d.readthedocs.io/en/stable/import_export.html),
[камеры OCP CAD Viewer](https://bernhard-42.github.io/ocp_viewer_docs/reset_camera/)
и нативный [AGENTS.md для Codex](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

- [build123d-mcp: validate.py](https://github.com/pzfreo/build123d-mcp/blob/59b2561218864c15cde08f19dff97be3906b6938/src/build123d_mcp/tools/validate.py):
  измерения ядра и явное покрытие проверок; инфраструктура MCP не переносилась.
- [cad-agent: loop.py](https://github.com/Agincourt-Systems/cad-agent/blob/d5130a95a5b2e1307a6ede2e0f75e9709a23dfba/src/cadx/loop.py)
  и [evaluate.py](https://github.com/Agincourt-Systems/cad-agent/blob/d5130a95a5b2e1307a6ede2e0f75e9709a23dfba/src/cadx/evaluate.py):
  цикл построить → измерить → сравнить → исправить и отчёт факт/ожидание/допуск.
  Здесь не создаётся отдельный автоматический агентный цикл или формат требований.
- [text-to-cad: snapshot-review](https://github.com/earthtojake/text-to-cad/blob/main/skills/cad/references/snapshot-review.md)
  и [snapshot.py](https://github.com/earthtojake/text-to-cad/blob/main/packages/cad/src/cad/engine/snapshot.py):
  фиксированные виды, свежесть изображений и отделение визуальных выводов
  от численных измерений. Их CAD-сервер и рендерер не устанавливались.

Исследовались исходники и документация этих проектов; сами внешние проекты
в пилоте не запускались. Новых зависимостей нет: Pillow уже присутствует
в зафиксированном окружении. Готовый стек не пересоздавался.

На этом Windows-компьютере штатный STL-экспорт возвращал ошибку при передаче
абсолютного пути с кириллицей; экспорт той же геометрии по относительному
ASCII-имени успешен. Поэтому экспорт временно меняет рабочий каталог на
каталог назначения и передаёт экспортёрам только имя файла. Исходный каталог
восстанавливается стандартным `contextlib.chdir`. Импорт STL в тесте использует
тот же приём. Исходники библиотек не менялись; имена экспортов остаются ASCII.

Источники установки: [build123d 0.13.0 на PyPI](https://pypi.org/project/build123d/0.13.0/),
