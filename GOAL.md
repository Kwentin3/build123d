# Issue #3 — Engineering Review Patterns

Статус: цифровой GOAL выполнен и доставлен отдельным Draft PR.
Поставка: https://github.com/Kwentin3/build123d/pull/4
Задание: https://github.com/Kwentin3/build123d/issues/3
База: main `05f611c4c3071323107812e0aef584bcd675da7c`.
Ветка: `work/issue3-engineering-patterns`, отдельный worktree
`output/issue3-worktree` исходной рабочей копии. Предыдущий GOAL — в Git.

Цель: выбор проверок по функции узла, а не только по форме BREP. Результат:
первичные источники, несколько условно загружаемых паттернов, минимальные
правки существующих пяти Skills/WORKFLOW и наблюдаемый перенос на другой узел.
Новый rule engine, каталог поверхностей, БД/MCP/оркестратор не нужны.

Границы: не менять принятые модели, зависимости, ядра библиотек и PR #2.
Часы — известная регрессия с явной внешней зависимостью от PR #2,
commit `0c365701b29654990fda00f66cb57ac102d5a70c`; исходники/STEP читаются
из первоначальной рабочей копии, не переносятся в эту ветку. Пересечение
отверстия с полостью само по себе не объявляется инженерным FAIL.

Независимый контроль: новый учебный держатель сменного фильтра, отдельные
исходники и варианты. Свежий агент получает назначение, необработанную
геометрию и Skills; не получает историю часов, предполагаемое нарушение,
ответы или оценочный валидатор. Изоляция на уровне переданного контекста,
не OS sandbox. Сохраняются точный brief, входные SHA, запросы недостающих
данных, реально выполненные измерения и ограничения вывода.

Приёмка:

- первоисточники DFMA, FMEA, допуски/GD&T, крепёж, traceability и CAD checks;
- небольшая применимая выборка: триггер/функция/отказ/геометрия/неизвестное/вывод;
- паттерны активируются по назначению, не требуют читать всё для малой правки;
- аудит этапа пропуска в старом workflow и регрессия часов;
- независимый агент выбирает проверку, задаёт вопросы и измеряет геометрию;
- валидный BREP может дать функциональный FAIL; неизвестное — NOT_CHECKED;
- текущие STEP после импорта, meaningful tests и полный pytest;
- Draft PR от main без смешивания с PR #2, проверка поставки и уборка.

Ресурсы: общий Windows executor, один heavy, 2 GiB/32 процесса, срок до900с;
RunId для наблюдения и адресной остановки. Все независимые проверки разделяют
heavy-слот. Новые зависимости и новая служба не планируются.

Делегировано: исследование первоисточников; read-only регрессия часов.
Основной агент отвечает за выбор интеграции, контрольный опыт и поставку.
Выбраны три справочника: attachment/load path, functional fit, assembly/service.
DFMA/FMEA/traceability адаптированы в выбор функции/критерия, DFM сохранён у
выбранного процесса. Изучены десять первоисточников; NASA PDF прочитан через
bounded download и временный pypdf после web-timeout, платные таблицы не нужны.
Пять Skills прошли штатный quick_validate через временный PyYAML, ссылки проверены.
