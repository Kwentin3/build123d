# Работа с CAD

Выбирай только затронутые шаги. Для изменения отверстия обычно достаточно
задания → правки параметра → измерений/экспорта → отчёта. Новое изделие
и производственный выпуск требуют большего объёма.

| Шаг | Что должно быть понятно для перехода дальше |
| --- | --- |
| Требования | Назначение, размеры/единицы, обязательные свойства и артефакты; неизвестное явно отмечено |
| Подход | Существующая модель/операции подходят; предметные ограничения остаются у изделия |
| Геометрия | Редактируемый Python, именованные параметры, валидное ожидаемое число тел |
| Сборка, если нужна | Положение, контакты, зазоры, пересечения и допустимая последовательность движений |
| Проверка | Фактические измерения против задания, отрицательные случаи, STEP после импорта |
| Производство, если нужно | Выбран процесс; контуры, единицы и количества проверены; непроверенный fit указан |
| Выпуск | Только текущие файлы, отчёт с хэшами, ограничения и необходимые документы |
| Изменение | Зафиксирована новая цель; повторены зависимые проверки; старый отчёт не принят как текущий |

FAIL возвращает к конкретному параметру, построению, размещению или экспорту.
Техническая ошибка возвращает к неисправной операции; она не доказывает
инженерного дефекта. NOT_CHECKED читается вместе с причиной: обязательную
проверку нужно выполнить, необязательную — честно оставить открытой.

Измеренные свойства не подменяют требования. Не исправляй тест изменением
ожидания только ради PASS. BREP-valid, правильный объём и снимок подтверждают
разные вещи. Геометрия не доказывает прочность, термостойкость или натурную сборку.
В мангале есть геометрические sweep-проверки поступательных траекторий
с ограничениями поверхностей; это не физическая динамика.

Для каждого изменения:

1. Прочитать выбранную модель, задание и Git diff. Выбрать необходимые Skills.
2. Править минимальный участок. Для испытания — отдельная копия/каталог output.
3. Запустить прежний CLI, прочитать свежий `report.json`, затем тесты модели
   и `.venv/Scripts/python.exe -m pytest -q` (Linux: `.venv/bin/python`).
4. Сопоставить measurements/expected с заданием, разобрать FAIL и NOT_CHECKED.
   Проверить хэши входов и файлов. При изменении условий повторить затронутую проверку.
5. Если запрошена визуальная приёмка, получить `--screenshots` в существующем
   viewer и открыть новые PNG. Не переносить старый visual review на новую редакцию.
6. Обновить существующую запись задачи: принятое решение, evidence,
   незакрытые пункты и следующий шаг. Убрать только свои временные ресурсы.

При новой сессии начать с AGENTS.md → cad-entry → README конкретной модели,
задания и Git diff. Сравнить хэши отчёта с файлами; при несовпадении или
отсутствии привязки повторить нужный запуск. Восстановление не требует истории
чата, если исходные требования и решения сохранены рядом с проектом.
