# Локальная правка существующей модели

Сначала прочитай задание, Git diff и README выбранного изделия. Обычным текстом
запиши исходную редакцию, разрешённый признак/параметры, защищённые тела и их
положение, сопряжения, нужные проверки и результаты. Новый шаблон задания не нужен.

До редактирования сохрани принятую геометрию отдельно. Git сохраняет Python;
STEP/BREP сохраняет измеряемую форму. SHA привязывает конкретные файлы, но не
доказывает равенство формы и подлинность отчёта. Не пересоздавай baseline из
уже изменённого кода. Не меняй общие тела baseline на месте.

## Пластина: только диаметр центрального сквозного отверстия

Сохрани STEP принятой пластины. В отдельной копии `model.py` измени
`HOLE_DIAMETER`, оставив `validation.py` рядом и структуру `models/plate/`
с `requirements.txt` в корне копии. Затем запусти её прежний CLI:

```powershell
.\.venv\Scripts\python.exe models/plate/model.py --bore-baseline output/accepted/plate_100.step --output-dir output/plate/bore_variant
```

`check_bore_change(before, after, expected)` заполняет измеренное старое отверстие
в принятом теле и вырезает только заданный новый диаметр. Всё остальное, включая
мировое положение внешнего тела, защищено. Проверяются исходное тело и повторный
импорт STEP; `bore_change` и `step_bore_change` обязательны при данном флаге.
Допуск необъяснённой симметрической разности — **0,001 мм³**. Это контракт этой
пластины, не проверка произвольного смещения отверстия или иных форм.

## Мангал 2.1: перераспределение вертикального хода направляющей

Python API для варианта без изменения исходников:

```python
from dataclasses import replace
from models.mangal_v21.model import Params, make_model, run
from models.mangal_v21.validation import validate_geometry

p = Params()
before = make_model(p)  # До изменения; принятие базы проверить отдельно.
assert all(c['status'] == 'PASS' for c in validate_geometry(before, p).values())
q = replace(p, guide_up_allowance=.8)
code = run(q, 'output/mangal_v21/guide_variant', guide_baseline=(before, p))
```

При редактировании самого генератора используй базу, сохранённую **до** правки:
например, пять отдельных STEP `side_1.step`, `side_2.step`, `end_1.step`,
`end_2.step`, `bottom.step` с явной привязкой filename → label и сохранёнными
`Params`. Сверь их SHA и исходную принятую редакцию. Не создавай `before`
повторным вызовом уже изменённого генератора. API принимает `{'parts': [...]}`
вместо полного исходного словаря; состояние acceptance остаётся обязанностью
вызывающего. Отчёт содержит параметры/габариты/объёмы переданной базы, но сам
по себе не удостоверяет её происхождение. Отдельный assembly STEP может
потерять уникальные occurrence labels повторных деталей; такой неоднозначный
вход отклоняется. Не угадывай соответствие по индексу грани или порядку тел.

`check_guide_change(before, after, p, q)` разрешает только `guide_up_allowance`.
Суммарный ход остаётся тем же: нижние окна обоих торцов с dogbone-вырезами
перемещаются по Z. Ожидаемые вырезы берутся из реального принятого тела,
а не повторно из проверяемого генератора. Две стенки и дно должны совпасть
целиком; у торцов защищено всё вне точного перенесённого выреза. Допуск
необъяснённой симметрической разности — **менее 0,01 мм³** на деталь.
Ошибка Boolean, неполные/повторные метки или иной параметр дают отказ.

`run(..., guide_baseline=(before, p))` включает проверку в существующий отчёт
и код выхода. Полные `validate_geometry`, STEP roundtrip, DXF и документы
остаются. `added_mm3`/`removed_mm3` описывают всё изменение; `unexpected_mm3`
показывает отличие от разрешённого результата. Нулевой объём в допуске не
гарантирует отсутствие микродефекта меньше допуска. Метки должны быть уникальны.

## Как изучить узел и выбрать проверки

1. Прочитать cad-entry и README выбранной модели. Найти её `Params`, `parts`
   и `motions` через `rg`. При необходимости построить текущую небольшую
   модель и вывести только label, bbox, volume и нужную запись движения.
2. Искать выбранное имя параметра по семейству модели; читать его определение,
   использования и непосредственные imports. Дальше — только затронутый узел,
   соседние детали и проверки. Не загружать в контекст тысячи граней.
3. Размер отверстия: измерения признака, защищённая форма, STEP/STL и отчёт.
   Паз сборки: ещё сосед, зазоры, пересечения, зависимые движения, STEP/DXF,
   BOM/инструкции. При неясном влиянии проверять шире. Полный pytest обязателен.
4. Разделить требуемое, необходимое сопутствующее и непреднамеренное. При
   последнем остановить приёмку, исправить копию и повторить проверки.

Это выборочное чтение контекста, не ленивое построение геометрии: OCCT может
собрать всю небольшую модель. Отдельный граф/индекс не хранится. Применимость
к большим сборкам и экономия токенов здесь не измерены.

Существующие пересечения проверяют статическую позу; пробы зазоров — заданное
сопряжение; sweep — непрерывное заданное линейное движение для поддерживаемых
поверхностей. Несколько поз не доказывают весь путь. Ни одна из этих проверок
не моделирует трение, силы, гравитацию, прочность или физическую сборку.
